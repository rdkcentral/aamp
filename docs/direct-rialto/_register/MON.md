# MON register fragment

Rows for the Monitoring and diagnostics page (08). The parent agent finished the page after the page agent stalled, and checked each row against the code.

| ID | Location | Type | What and why | Risk/impact | Suggested improvement | Effort |
|---|---|---|---|---|---|---|
| MON-01 | `AampRialtoMonitorAV.cpp:onReportTick` | Limitation | While the pipeline is not `PLAYING` the sample tick returns at once, so the classification is frozen. The report tick keeps calling `SendMonitorAvEvent` with the last classification and stale positions, and the monitor is only stopped by `Stop()`, `Configure()` rebuilds or destruction. | Telemetry reports, for example, "ok" or "stall" for the whole of a pause. Dashboards built on MonitorAV events can be misleading. | Skip reports, or report a "paused" state, when the player is not `PLAYING`. | S |
| MON-02 | `AampRialtoMonitorAV.cpp:onSampleTick` (single `getPosition()` for both tracks) | Limitation | Rialto exposes one pipeline position, so the audio and video positions are always equal. `VideoFreeze`, `AudioDrop` and `AvSync` can therefore never be detected; only `Stall`, `Trickplay` and ok-style states are reachable. The file comment acknowledges this for `AvSync`. | A/V sync problems and single-track freezes go undetected, where the GStreamer monitor would report them. | Use per-source position (if Rialto adds it) or `getStats` rendered-frame deltas per source. Until then, document the reduced capability for telemetry consumers. | M |
| MON-03 | `AampRialtoPlayer.cpp:GetPositionMilliseconds`, `GetVideoPTS`; `AampRialtoPlayer.cpp:OnPosition` (empty) | Tech-debt | Every position query from any thread makes a synchronous `getPosition()` IPC call. Rialto's `notifyPosition` events are received but ignored (ARCH-14). | IPC load scales with how often AAMP and the application poll position (progress, PTS checks, MonitorAV, app API). There is latency on the calling thread. | Cache the last `notifyPosition` value with its timestamp and interpolate, falling back to IPC only when stale. | M |
| MON-04 | `AampRialtoPlayer.cpp:OnDuration` / `GetDurationMilliseconds` (`m_durationMs`) | Limitation | `m_durationMs` is set only by `notifyDuration` and is never reset by `Stop()` or `Configure()`. | After a channel change, progressive media can report the previous item's duration until Rialto sends a new one. HLS/DASH are not affected (AAMP uses the manifest). | Reset to 0 in `StopInternal()` / `BeginNewSession()`. | S |
| MON-05 | `AampRialtoPlayer.cpp:GetVideoPlaybackQuality` | Possible bug | Same item as THR-09. The header says only the AAMP monitor thread calls it, but the callers are application APIs (`PlayerInstanceAAMP::GetVideoPlaybackQuality`, JS bindings), so several application threads can call it concurrently. It writes an unguarded member and returns a pointer to it. | A data race and a torn or overwritten result. | Return by value or copy under a lock. | S |
