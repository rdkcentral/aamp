| LIFE-01 | `AampRialtoPlayer.cpp:Pause` | Possible bug | With no pipeline, `Pause(true)` logs a WARN and returns false before `CancelPlayRequest`, so a pending play request survives an explicit pause. | If a pipeline then appears (a rebuild in progress) the old request can issue `play()` after the user paused. A narrow window. | Cancel the request (and release `FragmentCaching`) before the pipeline check. | S |
| LIFE-02 | `AampRialtoPlayer.cpp:Pause(false)`, `StopBuffering` | Workaround | Both ungate and call `play()` directly, bypassing the controller's holds, to match the GStreamer reference where these are explicit AAMP commands. | A resume during a flush or before the position is resolved plays from an undefined position and can let data through gates that a pending flush expects to be closed. | Route them through `RequestPlay` (respecting `Flushing`/`PositionPending`), or document why the bypass is safe. | M |
| LIFE-03 | `AampRialtoPipelineSession.cpp:CreateAndLoad` (`FactoryUnavailable`, `CreateFailed`), `AampRialtoPlayer.cpp:CheckAllSourcesAttached` | Limitation | These failures only log at ERROR. `Configure()` returns with no pipeline, or `SourcesNotAttached` stays held, and no `NotifyPlaybackError` is sent. | The tune hangs until AAMP's own tune timeout (if any) fires, with no specific error code, which is hard to diagnose in the field. | Report `AAMP_TUNE_GST_PIPELINE_ERROR` (with retry enabled for transient Rialto server issues). | S |
| LIFE-04 | `AampRialtoPipelineSession.cpp:CreateAndLoad` (`LoadFailed`) / `AampRialtoPlayer.cpp:Configure` | Possible bug | After a `load()` failure the pipeline is kept and sources are created and attached, but the state machine stays `IDLE`. `onSourceAttaching()` and `CheckAllSourcesAttached` act only from `PIPELINE_CREATED`/`SOURCES_ATTACHING`, so `allSourcesAttached()` is never called. | A silent hang with injectors blocked. The pipeline exists, so `Stream()` records a request that can never be honoured. | Treat `LoadFailed` like `CreateFailed` (release the pipeline) and report an error. | S |
| LIFE-05 | `AampRialtoPlayer.cpp:WaitForFlushToComplete` / `PlayerStateMachine::waitForFlushComplete` | Limitation | The 5000 ms flush timeout is evaluated only inside a waiter. If `SEEK_DONE` is lost and nobody calls `Flush`/`Configure`/`Stop`, the player stays `FLUSHING` with the `Flushing` hold applied indefinitely. | A stall after a seek if the server drops `SEEK_DONE`. AAMP's underflow or progress logic may eventually retune. | Add a one-shot timer, armed in `IssueFlushSeek`, that abandons the flush. | S |
| LIFE-06 | `AampRialtoPlayer.cpp:Stop` (`keepLastFrame`) | Limitation | The parameter is accepted and logged but unused: Rialto `stop()` has no equivalent. | Behaviour differs from the GStreamer path for callers that rely on the last frame staying on screen (for example channel change). | Confirm the platform behaviour with Rialto, then implement or document it in the `StreamSink` contract. | S |
| LIFE-07 | `AampRialtoPlayer.cpp:Stream` | Limitation | `Stream()` before `Configure()` (no pipeline) is ignored and no request is recorded. | If AAMP ever calls `Stream()` before `Configure()`, playback never starts. No such path is known today. | Record the request regardless of the pipeline (the controller resets it on `Stop()`), or log at WARN. | S |
