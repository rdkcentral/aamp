| FLUSH-01 | `AampRialtoPlayer.cpp:ApplySubtitleSegmentPosition` | Workaround | After every `SEEK_DONE`, `setSourcePosition` is called on the subtitle source even though the pipeline-level `setPosition()` has already flushed it. Without the call, subtitles appear late, because the subtitle engine only learns the position on the next successful `SignalSubtitleClock()`. The code comment calls this a "suspected Rialto issue". It runs under `m_attachMutex` on the event thread (see THR-04). | An extra IPC call per seek, plus the lock coupling of THR-04. It hides a possible server bug. | Confirm with the Rialto owners. | FLUSH-02 | `AampRialtoPlayer.cpp:HandlePlaybackStarted` (no equivalent of `mSetPlayerRateAfterFirstframe`) | Possible bug | AAMP's slow motion (`SetSlowMotionPlayRate`) sets `mSetPlayerRateAfterFirstframe` and relies on the GStreamer sink's bus handler to call `SetPlayBackRate` after the first frame. direct-rialto never does this, so the slow-motion rate is probably not applied. Not verified end to end. | A feature gap: slow motion plays at 1x. | Check the flag in `HandlePlaybackStarted` (through the notifiable) and call `setPlaybackRate`. Add an L2 test. | S |
| FLUSH-03 | `AampRialtoPlayer.cpp:SeekStreamSink` -> `Flush(position, int rate, ...)` | Limitation | `SeekStreamSink` receives a `double` rate and casts it to `int` for `Flush()`, so fractional trick rates are truncated (0.5 becomes 0). | Any fractional rate reaching this path behaves as rate 0 or rate 1.
