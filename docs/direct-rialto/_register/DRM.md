|---|---|---|---|---|---|---|
| DRM-01 | `RialtoMediaKeySessionAdapter.cpp:generateDRMSession` (`onLicenseRenewal` lambda) and `generateKeyRequest` | Possible bug | `onLicenseRenewal` ignores the renewal message (`/*message*/`) and only starts AAMP's renewal thread. `generateKeyRequest` waits for a challenge only if `m_challengeReceived` is false, and that flag is reset only by `clearDecryptContext()`. During a renewal it is still true from the first licence, so the **original** challenge and URL are returned immediately and sent to the licence server. | Licence renewal (key rotation, licence expiry) can fail or obtain the wrong licence, causing playback failure on long-running or live content with renewals. Unconfirmed on devices. | In `onLicenseRenewal`, store the message as the new challenge (under `m_eventMutex`), as `OCDMSessionAdapter` does for key messages. Alternatively, reset `m_challengeReceived` when a renewal starts and wait for the new message. Add an L1 test. | S |
| DRM-02 | `RialtoMediaKeySessionAdapter.cpp:generateDRMSession` -> `RialtoMediaKeySystem::createSession("cenc", ...)` | Tech-debt | The adapter always passes `"cenc"`, so the `webm`/`keyids` mapping in `createSession` is never used. | Dead code; WebM or key-ID init data, if ever needed, would be sent as CENC. | Pass the init data type from the `DrmHelper`, or remove the mapping. | S |
| DRM-03 | `RialtoMediaKeySystem.cpp:MediaKeysClient::deregisterSession` | Limitation | Waits on `callbackDone` with no timeout for callbacks running on other threads. It is safe today only because no callback takes the adapter's `m_mutex`, which `clearDecryptContext()` holds during deregistration. | A future callback that takes `m_mutex` (or blocks on the network) would deadlock teardown silently. | Document the rule beside the callback lambdas, and add a long diagnostic timeout with an ERROR log. | S |
| DRM-04 | `RialtoMediaKeySystem.cpp:MediaKeysClient::onKeyStatusesChanged` / `RialtoMediaKeySessionAdapter` | Limitation | Key status changes after `KEY_READY` (`EXPIRED`, `INTERNAL_ERROR`, `OUTPUT_RESTRICTED` mid-playback) are only cached. Nothing notifies AAMP until the server reports a decryption `PlaybackError`. | Later, less specific errors (`AAMP_TUNE_DRM_DECRYPT_FAILED`) instead of an immediate, accurate DRM event. HDCP downgrades are not reported promptly. | Raise an AAMP DRM event (or trigger renewal) when a ready session reports a non-usable status. | M |
| DRM-05 | `AampRialtoPlayer.cpp:AttachSource` -> `AampRialtoMediaSource::attachOrUpdate` -> `AampDrmBridge::createSession` | Limitation | A blocking licence acquisition (worst case about 20 s with default timeouts and retries) runs on an injector thread while it holds `m_attachMutex`. It is deliberate (the source needs the mksId before it can create the Rialto source), but it is the root of ARCH-04 and THR-04. | Mute/CC calls on the control thread and `SEEK_DONE` handling on the Rialto event thread can stall for the whole licence fetch. | Acquire the session before taking `m_attachMutex` (protection params are already copied by `ProtectionFor`), then attach under the lock. | M |
